# ROS 2

Raspberry Pi 5 使用 ROS 2 Jazzy 连接实验控制、相机、显示、声音、记录、诊断和时间同步。

对日常使用来说，可以把 ROS 2 理解成一组长期协作的实验服务。

## 实验控制

实验控制服务负责：

- 读取锁定后的训练配置
- 准备本次实验需要的设备
- 执行预检
- 开始实验
- 暂停
- 继续
- 停止
- 中止
- 汇总实验状态

网页上的实验控制按钮最终都进入这套 ROS 2 控制链。

## 硬件控制

硬件控制服务连接 RoboMaster C Board。

它负责：

- 发送 Trial
- 接收 Trial 结果
- 读取转轮
- 读取电机状态
- 接收硬件事件
- 发送视觉刺激请求
- 处理奖励和行为反馈

运行时通信使用 ST-Link/SWD。

## 视觉刺激

视觉刺激服务直接控制 HDMI 刺激屏。

它维护：

- 当前刺激
- Gabor 参数
- 屏幕位置
- 转轮闭环位置
- 当前帧
- 显示状态

目标输出为 1920 × 1080 @ 60 Hz。

## 行为声音

声音服务根据训练流程播放：

- Go tone
- Error noise

播放开始时间会同步记录到实验数据中。

## 相机

相机服务管理 OAK-FFC-4P。

它负责：

- 识别相机
- 启动四路采集
- H.265 编码
- MJPEG 浏览器预览
- 保存帧信息
- 上报相机状态
- 自动恢复设备连接

当前使用 4 × 1280 × 800 @ 30 fps。

## 数据记录

数据记录服务保存整场实验的时间序列。

记录内容包括：

- 行为事件
- 刺激命令
- 刺激显示
- 声音
- 相机帧信息
- 设备状态
- 时间同步状态

实验结束时生成记录校验信息。

## 诊断与预检

诊断服务为网页“预检”提供结果。

检查内容包括：

- 设备在线状态
- 存储空间
- 相机状态
- 刺激屏状态
- 时间同步
- 实验记录状态

实验完成后，它继续生成质量报告。

## 时间同步

时间服务读取 C Board 捕获的 PPS。

网页可以看到当前时间同步状态。

实验事件保留硬件时间，方便后续把行为、刺激和视频放到同一个时间轴上。

## 自动恢复

设备服务持续监看 MCU 和 OAK 相机状态。

当设备连接发生异常时，系统会按固定顺序执行恢复，并把结果更新到网页状态中。

设备恢复完成后，操作者可以从网页重新执行预检并继续下一次实验。

## 开机后的服务

开机后主要有两组常驻入口：

- 实验控制服务
- 网页控制台

相机、刺激、记录等服务会随实验需要自动启动和停止。

## 日常查看状态

SSH 进入主机：

```bash
ssh ratRot
```

查看 ROS 2 节点：

```bash
ros2 node list
```

查看设备状态：

```bash
ros2 topic echo /rig/device_health
```

查看实验状态：

```bash
ros2 topic echo /rig/session/status
```

查看相机列表：

```bash
ros2 service call /rig/camera/get_inventory rig_msgs/srv/GetCameraInventory
```

查看时间同步：

```bash
ros2 topic echo /rig/time/status
```
