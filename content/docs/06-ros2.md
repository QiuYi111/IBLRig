IBL Rig 选择 ROS 2 的核心原因，不是“把所有东西都 ROS 化”。

它主要解决：

- 设备和能力生命周期；
- 清晰的消息合同；
- Session 编排；
- 服务/action；
- 诊断；
- 多进程边界；
- 可测试的 task compiler；
- 相机、刺激、记录、时间等模块的组合。

实时 Trial FSM、电机、奖励和安全仍在 MCU。

## Authority model

先记住这张表：

| 问题 | 权威 |
|---|---|
| Web / Supervisor 进程活着吗 | systemd |
| 某个功能能力现在应该存在吗 | Supervisor Runtime Graph |
| demanded capability 怎样启动/恢复 | capability 自己 |
| Session 能运行吗 | Supervisor preflight/state |
| 操作者想做什么 | Web / `rig_runtime` |
| MCU 卡死还能不能救 | MCU capability 内的 SWD watchdog |
| Host 丢失后输出是否安全 | MCU firmware |

这比“哪个 node 最重要”更关键。

## Runtime Graph

Boot 不会把所有硬件节点全部拉起来。

正常 idle：

```text
Supervisor: running
Web: available
Runtime Graph: empty
Camera: absent
Stimulus: absent
MCU capability: absent unless demanded
```

当 Web prepare 一个 session 时，只提交：

- session id；
- rig id；
- operating mode；
- immutable artifact hashes。

Supervisor 读取 artifact，自行决定该 session 需要什么 capability。

因此“某个节点没启动”不一定是故障；如果 graph 根本没需求它，absence 就是正确状态。

## MCU Gateway

当前代码基线把 production controller link 定义为 SWD。

Gateway：

- 独占 ST-Link owner lock；
- 通过固定 SRAM ABI 与 MCU 交换 record；
- 建立 link session；
- 对可靠消息使用 sequence + ACK；
- 重试同一个语义身份而不是产生第二次执行；
- 遇到 MCU reset 时重新建立 session；
- 不允许普通 data record 自己改变 link session。

Watchdog 与 Gateway 不应同时拥有 probe。

## Stimulus

Stimulus renderer 是独立 direct-KMS 进程。

Task compiler / MCU 输出的是语义请求，不是“在 ROS callback 里画一帧”。

流程大致是：

```text
MCU semantic output
  ↓
Gateway
  ↓
StimulusCommand
  ↓
direct-KMS renderer
  ↓
page flip
  ↓
StimulusPresentation ACK
```

真正用于科学时序的物理显示边沿应由 photodiode 捕获。

## Camera

DepthAI manager 自己管理：

- 设备身份；
- firmware；
- pipeline；
- native encoder；
- MJPEG preview；
- health；
- recovery。

原始视频直接写文件，ROS 2 只承担 metadata 和控制。

## daemon / systemd 体系

systemd 不负责每一个 capability。

Boot-persistent 的核心控制面主要是：

- `ibl-rig-supervisor.service`
- Rig Web socket/service

其它功能能力由 Runtime Manager 根据 Runtime Graph 启停，而不是给每个 ROS capability 都做一个永久 systemd unit。

另一方面，实验后的任务使用独立 service/path/timer，例如：

- analysis；
- NAS；
- W&B；
- Feishu；
- cleanup；
- failure notification。

这样外部网络服务失败不会拖住实时 session 主进程。

## 故障恢复

系统区分：

**进程退出**
- Runtime reconciler 做 bounded restart。

**进程活着但设备不再健康**
- 读取新的 DeviceHealth；
- 经过 grace period；
- 分级重启 capability / SWD reset / USB recovery；
- 三次后进入 cooldown。

恢复受 session 状态约束：

- RUNNING / PAUSED / STOPPING 等状态不会随意硬复位 MCU；
- 相机 recording/finalizing 时不做相机硬恢复；
- fault latch 不会被自动“恢复成功”清掉；
- 训练不会因为设备重新在线自动继续。
