# 与 IBL 原版对比

本章说明 IBL Rig 与 International Brain Laboratory（IBL）原版行为装置的关系：哪些部分保持兼容，哪些部分采用了不同的实现，哪些部分仍在验证。

逐项参数对比见 [Reference · IBL 对比](../../reference/ibl-comparison/)。

## 一句话概括

IBL 原版优化的是**跨实验室的科学可重复性**；IBL Rig 优化的是**系统可靠性与可扩展的交互能力**。

两者不是替代关系。IBL Rig 以 IBL 任务为兼容层，在其上扩展 IBL 原版不具备的能力。

```text
IBL Rig
│
├── IBL 兼容层
│   ├── ChoiceWorld 任务
│   ├── 训练阶段与自适应增益
│   └── IBL 行为语义
│
└── 平台扩展能力
    ├── 可编程力反馈转轮
    ├── 多视角视频与在线视觉
    ├── 网络化多 Rig 实验
    └── 自恢复与系统测试
```

## 兼容性分层

"兼容 IBL"在本平台中分为三层，各层状态如下。

| 层级 | 含义 | 当前状态 |
|---|---|---|
| 任务兼容 | 刺激参数、训练流程、增益规则与 IBL 协议一致 | 已实现 |
| 数据兼容 | 行为数据可导出为 ALF，接入 IBL 分析工具 | 计划中 |
| 行为兼容 | 小鼠学习曲线、心理测量曲线落在 IBL 基准分布内 | 验证中 |

任务层已对齐的主要参数：

| 参数 | IBL 协议 | IBL Rig |
|---|---|---|
| 刺激 | Gabor | Gabor |
| 刺激位置 | ±35° | ±35° |
| 空间频率 | 0.1 cycles/° | 0.1 cycles/° |
| Gabor σ | 7° | 7° |
| 响应窗口 | 60 s | 60 s |
| 基础静止时间 | 200 ms | 200 ms |
| 自适应增益 | 8 → 4 | 8 → 4 |
| 训练协议 | IBL behavior protocol | `ibl_pdf_v4_6` |

## 两种设计出发点

### IBL 原版：以科学标准化为中心

IBL 首先要回答：

> 不同国家、不同实验室、不同操作者，能否得到可比较的行为学数据？

因此它围绕 protocol、calibration、subject、training phase、Alyx 和 ALF 组织，并用多实验室数据证明了行为结果的可重复性。这是 IBL 最重要的资产。

### IBL Rig：以系统工程为中心

IBL Rig 首先要回答：

> 谁拥有实时控制？谁拥有实验状态？设备掉线后由谁恢复？重启后旧状态会不会污染新实验？

因此每类职责都有明确的归属：

| 职责 | 归属 |
|---|---|
| 物理实时控制 | STM32 / FreeRTOS |
| 电机、泵、同步输出、安全停止 | STM32 |
| 实验状态 | Supervisor |
| 节点与设备编排 | ROS 2 |
| 进程存活 | systemd |
| 用户意图 | 网页控制台 |
| 设备健康 | DeviceHealth |
| 行为事件 | 不可变事件日志 |
| 数据归档 | 实验后处理流程 |

## 实时控制：同一原则，不同实现

两套系统共享同一个正确原则：

> **主机决定 Trial，实时控制器确定性地执行 Trial。**

IBL 原版中，Python 生成 Bpod 状态机，Bpod 执行，结果返回后生成下一个 Trial。转轮、声音、视觉刺激分别由独立模块或进程处理。

IBL Rig 中，主机编译一个有界 Trial 发给 STM32，由同一个控制器执行 Trial 状态机、转轮读取、电机控制、奖励、同步输出和安全停止。

STM32 在功能上相当于：

> Bpod + 旋转编码器模块 + 电机控制器 + 安全控制器的融合。

## 通信架构

### IBL 原版

以 ChoiceWorld 为例，一个 Trial 涉及三种运行时（Python、Bpod 固件、Bonsai）和多种协议：

```text
Python
├── 串口 → Bpod 状态机
├── OSC / UDP → Bonsai（每个 Trial 的刺激参数）
├── Bpod → 编码器模块串口 → Bonsai（显示、冻结、居中等指令）
├── Bpod → 声卡模块，或 soft code → Python → 声卡
├── 子进程 → Bonsai 相机录制
└── TCP / UDP → 辅助采集电脑
```

这是科研装置长期演化的典型结构。关键的状态切换走硬件串口，刺激时间由 Frame2TTL 光电回读验证，因此时序质量有保障；但状态分散在多个进程，缺少统一的生命周期与故障语义。

### IBL Rig

通信按数据类型分层：

```text
操作者
 ↓ HTTP / WebSocket
网页控制台
 ↓ ROS 2 / DDS
Supervisor + 设备能力
 ↓ 控制器链路
STM32
 ↓ CAN / STEP-DIR / GPIO
电机、泵、同步信号
```

| 数据 | 通路 |
|---|---|
| 用户控制 | HTTP / WebSocket |
| 系统状态与编排 | ROS 2 |
| 控制器命令 | ST-Link / SWD |
| 电机 | CAN |
| 奖励泵 | STEP / DIR |
| 同步信号 | GPIO |
| 相机 | USB 3 |
| 录像 | 原生 H.265 文件 |

平台的原则是：

> 科学语义自己拥有；消息、生命周期、日志、恢复等通用基础设施，使用机器人与工业领域的成熟方案。

## 硬件对比

### 转轮：从输入设备到双向接口

IBL 原版的转轮是无源的，由旋转编码器测量位置和速度。转轮本质上是输入设备。

IBL Rig 的转轮连接 M2006 减速电机和 C610 电调，同时是传感器、执行器和力交互接口。控制器以 500 Hz 运行电机控制环，可产生阻尼、弹簧、惯性、棘轮、透明和自适应透明等手感。

这带来了 IBL 原版不具备的能力：

> **主动改变动物所处的机械环境。**

"透明模式"与无源转轮的机械等效性（惯量、摩擦、齿隙）正在通过台架测试验证。

### 奖励

IBL 原版的科学变量是奖励体积（µL），通过电磁阀开启时间校准得到。

IBL Rig 使用步进蠕动泵，每个脉冲的体积已校准（约 0.382 nL / pulse），具备双向、排气方便、每个脉冲可记录的优点。

当前正式配置按泵动作时长给水。平台将统一为与 IBL 相同的体积语义：

```text
目标奖励体积 (µL)
 ↓
泵校准
 ↓
脉冲数
```

### 声音

IBL 原版使用声卡和扬声器，go tone 为 5 kHz 纯音，错误反馈为白噪声。

IBL Rig 当前使用 STM32 板载蜂鸣器，声音与 Trial 使用同一个控制器计时。go tone 为 4 kHz / 100 ms，错误反馈为 2 kHz / 4 kHz 交替音，共 500 ms。

与 IBL 一致的声音方案（白噪声、声压校准）列入后续计划。

### 相机

| 项目 | IBL 原版 | IBL Rig |
|---|---|---|
| 训练装置 | 1 路，60 fps | 4 路 |
| 电生理装置 | 3 路，最高 150 Hz | — |
| 传感器 | FLIR | OV9782 × 1 + OV9282 × 3，全局快门 |
| 当前规格 | — | 1280 × 800，30 fps，H.265 |
| 高帧率 | 支持 | 单路可达 120 fps |
| 编码 | 主机端 | 相机端硬件编码 |
| 板载计算 | 无 | 支持神经网络推理 |

四路传感器接入同一个 OAK 设备，通过单根 USB 3 连接主机。

## 时序与同步

| 项目 | IBL 原版 | IBL Rig | 状态 |
|---|---|---|---|
| Trial 事件时间戳 | Bpod 硬件时钟 | STM32 硬件时钟 | 已实现 |
| 外部时间基准 | — | GPSDO PPS 输入 | 已实现 |
| 刺激出现时间 | Frame2TTL 光电回读 | 屏幕光电标记已绘制，硬件采集待接入 | 进行中 |
| 相机帧对齐 | 相机 GPIO / TTL | 相机时间戳 + 50 ms 窗口归组 | 外触发计划中 |

对行为训练而言，当前时序已经足够。面向电生理对齐的硬件级同步（光电二极管采集、相机外触发）是后续工作。

## 可靠性：两种含义

这是理解两套系统最重要的区别。

**IBL 的可靠性是科学可重复性：**

```text
相同协议
+ 不同实验室
+ 不同动物
→ 可比较的行为结果
```

**IBL Rig 的可靠性是系统可靠性：**

```text
重启、复位、USB 故障、网络中断、竞态、进程崩溃
→ 状态保持一致
→ 执行器保持安全
→ 数据可追溯
```

IBL Rig 的系统可靠性由 HIL / Chaos 测试验证。当前保留的实机长跑结果：

| 项目 | 结果 |
|---|---|
| 时长 | 20 min |
| 注入事件 | 1091 |
| 规则违反 | 0 |
| 确定性回归场景 | 48，全部通过 |

详见 [08 · Chaos / HIL](../08-chaos-hil/)。

理想的下一代行为学平台应同时具备两种可靠性。IBL Rig 已具备第二种，并正在通过等价性验证建立第一种。

## 运维与使用体验

| 项目 | IBL 原版 | IBL Rig |
|---|---|---|
| 登录 | Alyx | 飞书 |
| 界面 | 桌面程序 | 浏览器，支持远程访问 |
| 多人协作 | — | 控制权租约、接管、审计 |
| 预检 | 硬件校验 | 网页预检，限时完成 |
| 训练续接 | 按小鼠读取历史 | 按小鼠自动续接阶段、增益、奖励 |
| 在线监看 | 心理测量曲线、反应时 | 表现统计 + 四路视频预览 |
| 归档 | Alyx / FlatIron | NAS 逐文件校验 + W&B + 飞书索引 |

IBL 原版的在线分析（心理测量曲线、时间曲线）对行为神经科学家非常成熟；IBL Rig 更偏向设备运维，更像一台网络化的实验设备。

## IBL 原版仍然领先的地方

- **经过多实验室验证的行为学基准。** 这是 IBL 最核心的价值，也是 IBL Rig 验证行为兼容性的参照。
- **完整的数据生态。** Alyx / ONE / ALF 连接了大量公开数据和分析工具。
- **硬件级刺激时间测量。** Frame2TTL 光电回读是成熟方案。
- **高帧率多相机电生理配置。**

## 验证计划

IBL Rig 将建立一套与 IBL 原版的逐层等价性测试：

```text
屏幕光子
 ↓ 视觉几何
 ↓ 转轮力学
 ↓ 响应阈值
 ↓ 声音
 ↓ 奖励体积
 ↓ 事件时间戳
 ↓ ALF 导出
 ↓ 行为结果
```

| 类别 | 测量项 |
|---|---|
| 视觉 | 空间频率、视角、对比度、帧时间、光电回读延迟 |
| 力学 | 转轮惯量、摩擦、阈值、增益 |
| 声音 | 频谱、声压、起始延迟 |
| 奖励 | 平均体积、方差、漂移 |
| 时序 | 刺激到响应、响应到奖励、时间戳映射 |
| 行为 | 心理测量曲线、时间曲线、反应时、阶段进展、Trial 数 |
| 跨 Rig | 同型号多台装置之间的一致性 |

完成后，平台将同时具备：

```text
更好的工程实现
+
与 IBL 可比的科学结果
```

## 总结

| | IBL 原版 | IBL Rig |
|---|---|---|
| 核心资产 | 协议与数据标准 | 装置与系统架构 |
| 工程实现 | 实验室工具链逐年演化 | 机器人与工业架构 |
| 科学验证 | 多实验室验证完成 | 等价性验证进行中 |
| 转轮 | 测量 | 测量 + 交互 |
| 扩展方向 | 标准化范式 | 力交互、在线视觉、网络化实验 |

IBL Rig 的定位是：

> **兼容 IBL 任务的下一代行为学平台。**
